# HPA比較実験（全サービスHPA化）詳細結果

2026-07-13。email律速をSCALE_ALLで除去した上での「束ね vs 分離」比較。
スクリプト=`km2/experiments/hpa-percontainer-softirq.sh`（SCALE_ALL=1）、生データ=`km2/experiments/results-hpapercont-allscale.csv`。

## 1. 実験条件

| 項目 | 値 |
|---|---|
| 比較アーム | f3avg=束ね+Pod平均HPA / f3perc=束ね+コンテナ別HPA(ContainerResource) / normal=分離 |
| 束ねPod | frontend+recommendation+productcatalog を1Podに同居しlocalhost通信 |
| スケール対象 | 全アプリサービスに個別HPA（redisのみ固定=ステートフル） |
| HPA設定 | CPU目標70% / min1 / max4 |
| 負荷 | locust checkoutフロー（1周=3req: GET /product, POST /cart, POST /cart/checkout）、constant_throughput(1) |
| 負荷レベル | users 240 / 480、spawn rate 40 |
| サイクル | 3回（各サイクルで再デプロイ=レプリカ1リセット） |
| 各計測 | ウォームアップ3分→基線2.5分→本計測3分 |
| 環境 | MicroK8s単一ノード(~16vCPU), namespace=exp, Istio無し |
| 指標 | softirq/req=1リクあたり通信カーネルCPU(ms), rps, 総レプリカ数, fails |

## 6. 結論

- **u240(飽和前)**: 束ねの安定勝ち。rps +10%, softirq/req −32%, Pod数 12-14 vs 18。再現性あり。
- **u480(飽和近く)**: 束ねは最大 +28%(852 vs 664) だが双安定。コンテナ別しきい値は高い枝を掴みやすい(2/3 vs Pod平均1/3)。
- **softirq/req**: 束ね −32%〜−46% で一貫（co-locの通信削減効果は堅牢）。
- **トレードオフ**: 分離=堅牢だが頭打ち(~664固定・最多Pod) / 束ね=効率高いが単一HPA判定に賭ける脆さ(双安定)。email律速除去後も本質として残る。
