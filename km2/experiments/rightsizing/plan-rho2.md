# 計画: ρ の精度を上げる分離測定 (mix-cpu2)

作成 2026-10-09。**測定の結果を見る前にコミットする。** 解析の規則を後から変えたら、変更前の結果も併記する。

## 1. 目的

各サービスの ρ (view に対する CPU の増え方 ÷ buy に対する増え方) を、実測で、区間付きで求める。予測には使わない (ρ は実測で求めるものとする。ユーザ指示 2026-10-09)。

アヌビス点検 (2026-10-08) で、10/07 の測定 (`results-mix-cpu.csv`) には次の問題が指摘された:
- buy が 2 水準 (50, 100) しかなく、ρ と a = c/β (負荷の総量への反応) を分けられない。交互作用 (buy と view が同時にかかると足し算以上に増える) も推定できない。
- 3 サイクルでは区間が広い。cart と currency の差は 1 台時に区別できない。
- view の振り幅が小さく、ρ の差が利用率の差として小さくしか出ない。

## 2. 測定 (固定)

- スクリプト: `measure-mix-cpu.sh` (このコミットの版。休憩と冷却待ちのオプションを追加。既定の挙動は変わらない)。
- 構成: 分離 (`km2/normal/`)・HPA 無し・全サービス 1 台固定 / 2 台固定 (redis-cart は常に 1 台)。limits 上書き frontend / catalog 3000m、ad 1000m。GRPC_LB=1。
- 点 (17 点、周/秒): buy {0, 25, 50, 75, 100} × view {0, 75, 150, 300}。ただし b0v0、b75v300、b100v300 は除く。
  `v75 v150 v300 b25 b25v75 b25v150 b25v300 b50 b50v75 b50v150 b50v300 b75 b75v75 b75v150 b100 b100v75 b100v150`
- 6 サイクル。1 台と 2 台のどちらを先にするかはサイクルごとに入れ替える。点の順番はブロックごとにシャッフルする。
- WARM 60 s / MEAS 180 s (窓は両端 10 s を削った 160 s)。デプロイごとに慣らし負荷 b100 を 180 s 流して捨てる。
- マシンを休ませる: 各点の前に CPU (coretemp) の最高温度が 70℃ 以下になるまで待つ (最長 600 s)。点の後に 60 s 休む。

## 3. 解析 (固定)

- **データの単位**: サービス s・台数 n・サイクル k・点 m の CPU 使用量 D [m] (同じ Deployment の Pod の合計)。
- **除外**: 次のどちらかに当たる (点, サイクル, 台数) は、全サービスまとめて除外し、件数を報告する。
  - buy か view の取りこぼし (dropped_win) が、目標周回数 × 計測秒数の 1% を超える。
  - そのサービスの絞られた割合 (throttle_pct) が 5% を超える。この場合は、そのサービスだけを除外する。
- **ρ の主推定**: (s, n) ごとに、全 17 点 × 有効サイクルで最小二乗 D = c + β·buy + ν·view を当て、ρ = ν/β とする。a = c/β も併記する。
- **区間**: サイクル単位のブートストラップ (サイクルを復元抽出、2000 回、パーセンタイル 95%)。参考として、サイクルごとに当てた 6 個の値の t 区間も出す。24 行 / 102 行を独立とみなした OLS の標準誤差は使わない。
- **サービス間の比較**: 同じ点・同じサイクルの 2 サービスで差 ρ_s − ρ_t を取り、その差のブートストラップ区間で判定する。95% 区間が 0 を含まなければ「区別できる」とする。
- **感度 (副)**: 次の条件で当て直した結果を並べる。
  - 交互作用項 γ·buy·view を入れる。
  - buy>0 の点だけを使う (10/07 と同じ範囲)。
  - buy ≤ 50 の点だけを使う、buy ≥ 50 の点だけを使う (領域による ρ の違い)。
- **モデルを使わない比較 (副)**: 基準点 b50v150 で正規化した需要の形 P_s(m) = D_s(m)/D_s(基準) を出し、対の比 P_s/P_t をサイクルごとに出す。
- 10/07 の結果 (n=1 の ρ: front 0.29 / catalog 0.29 / reco 0.31 / cart 0.13 / currency 0.19 / 買う側 ≈ 0 / ad 0.76) と並べる。
