### ★原稿から削った記述(ユーザ判断。復活させる場合の記録)

### ★保留: 77% の由来をどこかに入れる(ユーザが「別のところに入れる」と保留 2026-09-10)
原稿の §5.1「増設ライン77%」と §5.2 の不等式「93/r ≤ 0.77」「113/(2r) > 0.77」に出てくる **77% には現在どこにも根拠がない**(HPA 設定の記述をユーザが削除したため)。
**由来 = HPA の目標利用率 70% × 許容幅(tolerance) 1.1 = 77%**。Kubernetes の HPA は既定で 10% の許容幅を持ち、利用率が目標の 1.1 倍を超えて初めて増設する。
入れ方の案(行数を増やさない): §5.1 初出を「増設ライン (目標70\%＋許容幅10\%) である77\%」とする。
※ HPA 設定そのものの段落(ContainerResource / 目標利用率70% / 様子見窓)はユーザ判断で §3 から削除済み。復活させず、77% の由来だけをどこかに入れる方針。

### softirq という語の出どころ(2026-09-10 にユーザから質問)
造語ではなく、実験スクリプトが使う Prometheus メトリクスのラベル名そのもの: `node_cpu_seconds_total{mode="softirq"}` (`km2/experiments/*.sh`)。`mode` は Linux `/proc/stat` の CPU 時間区分(user/system/idle/iowait/irq/softirq/…)。パケット送受信処理は softirq で実行されるので、この時間＝通信処理の CPU 時間。
原稿では「softirq モード」→「**softirq の CPU 時間**」に簡略化(ユーザ判断)。定義箇所では「CPU 時間」を残す(softirq 単体は機構名であって量ではないため)。§4・§5.3 の言及は「softirq で −32%」のような短縮形でよい。
