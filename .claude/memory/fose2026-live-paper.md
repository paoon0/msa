## 題目と着地点(ユーザ決定)
題目案: **「オートスケール環境におけるマイクロサービスの部分集約 —— 効果と相手選びの2軸」**
着地点: **「主成分(ワークロード成分)が異なり、さらにエッジが太いサービスを組み合わせることが問題」**

★ただし **Online Boutique にはこの象限が存在しない**(実測: 成分をまたぐエッジは5本・通信量の9.6%・最大2.6%。同成分が90.4%)。構造的理由=太いエッジは頻度の高い経路の上にあり、その経路上のエッジは両端とも同成分で駆動される。
⇒ **「実証した」とは書かない。**「2軸の提示 + 本アプリでは衝突しなかったという観測 + 一般には衝突しうる見通し」の形にする。ライブ論文(初期段階の成果)の趣旨には合う。

## 構成(6節・下書き済)
1. はじめに: 粒度問題 → 部分集約 → 先行研究[ICTer2022, NotNets]はメリットを示すが**Kubernetesのオートスケール環境を対象としていない**
2. 部分集約とHPAの干渉: Podは分割不可 → **Δ = Σ(N − n(s))×r(s)**。損は引きずられた側の枠に比例
3. 実験環境: Online Boutique / MicroK8s 16コア / k6開ループ / コンテナ別HPA 70% / 枠=(アイドル+1リクCPU×100)÷0.7
4. **予備実験(メリット)**: 表1 = 7月の users240、rps 639.2±32.5 → 704.7±5.9(**+10.2%**)、softirq −32%、Pod 18.3→14.3
5. 効果は組み合わせに依存
   - 5.1 **枠で消せる損**: 購入100で FE+email +1077m(email が1台で83%>77%、枠が7%不足)/ 購入150 で全4ペア **0**
   - 5.2 **枠では消せない損**: 閲覧0 +1077m / 閲覧300 +119m(**9倍・引きずる側が反転**)。両立する枠は存在しない(r≥121 かつ r<73)
   - 5.3 **2軸**: エッジ通信量の実測(同成分90.4% / 異成分9.6%)
6. 考察: 2軸。危険象限は本環境では空。単一ノードでoverlayなし。Sock Shop等での検証が今後
